# **RepoGuide — Product Vision & Principles**

## **Mission**

RepoGuide exists to become the engineering tool that developers instinctively consult before making changes to production software. The goal is not to build another AI coding assistant, but a system that develops a deep, persistent understanding of software repositories and helps developers make safer, faster, and more informed engineering decisions.

## **Core Question**

Every feature should answer at least one important engineering question developers regularly struggle with:

* Understanding architecture  
* Navigating large repositories  
* Assessing change impact  
* Debugging complex systems  
* Evaluating implementation options  
* Reducing engineering risk

## **Guiding Principles (use these as audit criteria)**

1. **Long-term value over short-term speed.** Optimize for durable product value, not fast feature delivery.  
2. **Understanding over code generation.** When multiple implementation approaches are possible, prefer the one that most improves a developer's understanding of their codebase over the one that simply produces more code.  
3. **Compounding value.** The product should become more valuable the longer it's used. Prefer capabilities that accumulate knowledge, improve understanding over time, and reduce repeated work — not one-shot outputs that reset in value every session.  
4. **Scale-agnostic by design.** Every capability should be designed for repositories of every size, from small personal projects to large enterprise codebases. Avoid decisions that only work for small repos unless they can evolve naturally to larger systems.  
5. **Reduce cognitive load.** The best feature removes complexity from the developer's workflow rather than introducing new concepts they must learn.  
6. **Stack-agnostic durability.** Favor solutions that remain useful regardless of programming language, framework, repo size, or underlying AI model. Long-term value should come from software engineering understanding, not dependence on any particular technology.  
7. **Trust through evidence, not confidence.** Developer trust is the product's most valuable asset. Earn it through accuracy and transparency. When uncertainty exists, communicate it clearly instead of hiding it — it's better to admit uncertainty than present unsupported conclusions.  
8. **Incremental, mission-aligned progress.** Prefer improvements that strengthen the overall product vision over isolated features that don't contribute to the long-term mission.

## **Audit Questions (ask of every feature/decision)**

* Does this make RepoGuide more useful to developers?  
* Does this improve a developer's ability to understand and safely modify software?  
* Will this still be valuable five years from now?  
* Does this move RepoGuide closer to becoming an essential engineering tool rather than another AI interface?
